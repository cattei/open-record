本文件说明 open-record（录音助手）的使用范围、许可关系与责任边界。

需要先讲清楚一件事：本文件里同时存在两类内容——**有法律效力的许可条款**（仓库根目录的 `LICENSE`，MIT）和**作者的意愿与请求**（"不欢迎商用"）。两者不是一回事，混着说会误导人，所以第 3 节专门拆开讲。

---

## 1. 为什么开源

录音是很私人的东西。闭源的录音软件，你无法确认音频被送到了哪里、有没有被传走，只能选择相信厂商。

这个工具开源，就是为了让这件事不烧心：代码全在 `app/` 目录下，你可以自己读、自己跑、自己核对它有没有联网、有没有偷偷上传。

需要说明：**开源意味着代码可审计，不等于任何人可以把它当商品拿去卖**。后者见第 3 节。

## 4. 录音的法律责任

这一节比许可条款重要得多。

**录音是否合法，完全取决于你所在地的法律和具体场景。** 同一段录音，在一个司法辖区可能完全合法，在另一个辖区可能构成违法。本工具只提供技术能力，**不提供任何法律意见**，也无法判断你的用法是否合规。

需要你自行确认的常见问题：

| 问题 | 说明 |
|---|---|
| 是否需要对方同意 | 部分辖区要求对话各方同意（all-party consent），部分只要求一方同意，差异极大 |
| 录音用来做什么 | 私人备忘、取证、公开发布、对外提供，适用规则不同 |
| 是否涉及商业秘密或他人隐私 | 录到第三方内容时，风险不只来自"录音"这个动作本身 |
| 场景是否有特殊规定 | 职场、教育、医疗、金融等场景通常有额外法规或内部制度约束 |
| 人不在场时的自动或远程录音 | 这类用法在很多司法辖区高度敏感，通常需要更严格的合法依据 |

关于最后一条，必须点明：本工具具备远程启停能力（可选的飞书远程控制），**能力存在不等于用法合法**。"我不在场，机器替我录"这种做法在多数司法辖区属于高风险用法，请先确认合法依据再使用。

**结论：使用者自行承担全部法律责任。** 作者不鼓励、也不支持任何违法录音用途。

## 5. 数据与隐私

- 录音默认只写入本机 `recordings/` 目录，不经过作者，也没有云端存储与账号体系。
- 作者不收集任何数据。代码中没有统计、埋点或回传，可自行审计 `app/` 全部源码。
- 两处例外，都属于**你主动开启**的可选功能，如实说明如下：

| 可选功能 | 默认 | 数据流向 |
|---|---|---|
| 飞书远程控制 | 关闭 | 启用后，指令与录音文件会经你自建的飞书企业应用发到飞书，数据经过飞书服务器，受你与飞书的协议约束 |
| 语音转写 | 关闭 | 启用后需下载模型，会访问模型源站；转写在本机完成 |

- 本机 HTTP 控制口默认只监听 `127.0.0.1`。若你把地址改成对外地址、又留空 token，等于把控制能力开放给任何能访问该端口的人，风险由你承担。
- 录音内容的保管、备份、加密、删除，以及是否构成个人信息处理的合规义务，**全部由使用者负责**。程序不做自动清理，录多少留多少。
